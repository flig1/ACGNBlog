## 1. 概述

### 1.1 反写插件简介

反写插件是K/3 Cloud系统中用于处理单据间数据反写的重要扩展点。当单据保存、审核时，系统会根据业务流程追踪信息，将数据反写到上游单据；当单据反审核、删除时，系统会根据历史反写记录，回滚反写数据。

反写插件允许开发者干预反写过程的各个环节，实现自定义的反写逻辑，满足复杂的业务需求。

### 1.2 反写流程概述

反写过程的主要步骤如下：

1. **寻找源单**：根据单据的关联子表记录，寻找到单据的直接源单
2. **构建业务流程**：寻找到直接源单所在的业务流程实例，将本单追加到业务流程实例中
3. **搜索反写规则**：搜索本单的全部反写规则
4. **判断反写条件**：判断本单的各行是否符合各个反写规则的反写条件
5. **执行反写规则**：循环执行反写规则，包括：
   - 批量读取需要反写的全部源单
   - 逐行反写数据到源单
   - 判断源单是否达成关闭条件
   - 判断源单反写后是否超额
   - 批量保存本次反写的源单

### 1.3 核心概念解析

| 概念         | 描述                                                         |
| ------------ | ------------------------------------------------------------ |
| 反写规则     | 定义了如何将数据从目标单反写到源单的规则，包括反写字段、反写条件、反写量等 |
| 业务流程跟踪 | 记录单据间的关联关系，用于追溯业务流程和执行反写             |
| 源单         | 被反写数据的单据，通常是上游单据                             |
| 目标单       | 发起反写的单据，通常是下游单据                               |
| 反写量       | 需要反写到源单的数据量，如数量、金额等                       |
| 反写条件     | 触发反写的条件，如状态、数量等                               |
| 关闭条件     | 判断源单是否可以关闭的条件                                   |
| 超额检查     | 检查反写后源单数据是否超过原始数据的检查                     |

## 2. 基础部分

### 2.1 反写插件基类与注册

**反写插件基类**：

```csharp
Kingdee.BOS.Core.BusinessFlow.PlugIn.AbstractBusinessFlowServicePlugIn
```

**注册方式**：

1. 反写插件需要部署到K/3 Cloud站点目录的`Website\Bin`子目录
2. 在BOS设计器中，注册到单据的关联配置属性中

**注意事项**：

- 单据的反写插件是公用的，会覆盖本单全部反写规则的执行过程
- 在反写插件中，需要对当前执行的反写规则进行判断，避免影响其他反写规则

### 2.2 公共属性详解

| 属性名          | 描述                                   | 用途                       |
| --------------- | -------------------------------------- | -------------------------- |
| BusinessInfo    | 当前单据元数据信息                     | 获取单据结构、字段信息等   |
| Context         | 上下文                                 | 获取登录信息、数据库连接等 |
| DynamicObjects  | 当前选择单据数据信息                   | 获取单据数据               |
| LinkEntity      | 当前单据BOSIDE中配置的单据关联配置信息 | 获取关联配置               |
| OperateOption   | 当前操作的额外选项信息                 | 传递额外信息               |
| OperationNumber | 当前操作，操作码                       | 判断当前操作类型           |

### 2.3 事件体系架构

反写插件的事件体系按照反写流程的顺序触发，主要包括以下阶段：

1. **准备阶段**：BeforeTrackBusinessFlow、BeforeCreateArticulationRow
2. **规则执行阶段**：BeforeWriteBack、AfterCustomReadFields
3. **数据处理阶段**：AfterCommitAmount、BeforeCloseRow、AfterCloseRow、BeforeCheckHighLimit、AfterCheckHighLimit
4. **保存阶段**：BeforeSaveWriteBackData、AfterSaveWriteBackData
5. **完成阶段**：FinishWriteBack

## 3. 事件详解

### 3.1 BeforeTrackBusinessFlow

**触发时机**：分析单据体的关联子表，提取关联关系之前

**应用场景**：取消记录业务流程跟踪信息，取消本单的全部反写

**关键属性**：

- `Cancel`：是否取消本次反写

**示例代码**：

```csharp
public override void BeforeTrackBusinessFlow(BeforeTrackBusinessFlowEventArgs e)
{
    // 订货下达要货申请流程，不做业务流程跟踪处理
    e.Cancel = true;
}
```

### 3.2 BeforeCreateArticulationRow

**触发时机**：构建下游单据体行的关联信息数据包之前

**应用场景**：取消记录本行业务流程跟踪信息，取消本行反写

**关键属性**：

- `Entity`：关联主实体的元数据信息
- `ActiveRow`：关联主实体的当前焦点行数据包
- `Cancel`：是否取消本行关联信息数据包的创建

**示例代码**：

```csharp
public override void BeforeCreateArticulationRow(BeforeCreateArticulationRowEventArgs e)
{
    // 某些条件下，取消本行的关联信息创建
    if (某些条件)
    {
        e.Cancel = true;
    }
}
```

### 3.3 BeforeWriteBack

**触发时机**：正式开始执行某条反写规则前

**应用场景**：判断当前反写规则是否为本插件关注的规则，取消执行本条反写规则

**关键属性**：

- `SourceBusinessInfo`：上游单据元数据信息
- `Rule`：本次采用的反写规则
- `Cancel`：是否取消本次反写

**示例代码**：

```csharp
private bool _thisIsMyRule = false;

public override void BeforeWriteBack(BeforeWriteBackEventArgs e)
{
    // 判断当前规则是否为本插件关注的反写规则
    if (e.Rule.Id.EqualsIgnoreCase("MyRuleId"))
    {
        _thisIsMyRule = true;
    }
}
```

### 3.4 AfterCustomReadFields

**触发时机**：正式开始执行某条反写规则前，平台加载完反写规则中使用到的相关源单字段后

**应用场景**：添加反写过程中需要用到的源单额外字段

**关键属性**：

- `SourceBusinessInfo`：上游单据元数据信息
- `Rule`：本次采用的反写规则

**关键方法**：

- `AddFieldKey(string fieldKey)`：添加需要加载的字段

**示例代码**：

```csharp
public override void AfterCustomReadFields(AfterCustomReadFieldsEventArgs e)
{
    if (_thisIsMyRule == true)
    {
        e.AddFieldKey("FBillTypeID");
        e.AddFieldKey("FPlanDate");
        e.AddFieldKey("FDeliveryDate_Plan");
    }
}
```

### 3.5 AfterCommitAmount

**触发时机**：对每个源单行完成反写之后

**应用场景**：完成源单数据包反写后，干预源单记录，填写额外字段或修改已填写的字段值

**关键属性**：

- `SourceBusinessInfo`：上游单据元数据信息
- `Rule`：采用的反写规则
- `SourceDataObject`：上游单据整体数据包
- `SourceActiveRow`：上游单据实体焦点行的数据包（本次反写的源单数据）
- `OperationName`：当前操作的名称
- `SourceCommitField`：上游单据接收反写值的字段元数据信息

**示例代码**：

```csharp
public override void AfterCommitAmount(AfterCommitAmountEventArgs e)
{
    if (_thisIsMyRule == false) return;
    
    if (e.OperationName.EqualsIgnoreCase("Save"))
    {
        string srcFormId = e.SourceBusinessInfo.GetForm().Id;
        // 处理反写后的数据
        if (srcFormId.EqualsIgnoreCase("SAL_SaleOrder"))
        {
            // 处理销售订单的反写
        }
    }
}
```

### 3.6 BeforeCloseRow

**触发时机**：每次判断源单行关闭条件之前

**应用场景**：取消对源单行的关闭处理

**关键属性**：

- `SourceBusinessInfo`：上游单据元数据信息
- `Rule`：本次反写采用的反写规则
- `SourceDataObject`：上游单据整体数据包
- `SourceActiveRow`：上游单据实体焦点行数据包
- `Cancel`：是否取消本次关闭操作

**示例代码**：

```csharp
public override void BeforeCloseRow(BeforeCloseRowEventArgs e)
{
    // 发货通知单出库已关闭，取消本次反写关闭源单的操作
    if (_thisIsMyRule && e.SourceDataObject["CLOSESTATUS"].ToString().EqualsIgnoreCase("B"))
    {
        e.Cancel = true;
    }
}
```

### 3.7 AfterCloseRow

**触发时机**：处理源单行关闭逻辑之后，不管源单行是否符合关闭条件

**应用场景**：干预关闭源单后相关业务逻辑

**关键属性**：

- `SourceBusinessInfo`：上游单据元数据信息
- `Rule`：本次反写采用的反写规则
- `SourceDataObject`：上游单据整体数据包（支持修改）
- `SourceActiveRow`：上游单据实体焦点行数据包（支持修改）
- `EntryCloseFieldStatus`：填写到上游单据体行上的关闭状态值
- `BillCloseFieldStatus`：填写到上游单整体数据包上的关闭状态值

**示例代码**：

```csharp
public override void AfterCloseRow(AfterCloseRowEventArgs e)
{
    if (e.SourceBusinessInfo.GetForm().Id == "SAL_SaleOrder")
    {
        if (e.EntryCloseFieldStatus.EqualsIgnoreCase("B"))
        {
            e.SourceActiveRow["DeliveryStatus"] = "C";
        }
        else if (Convert.ToDecimal(e.SourceActiveRow["BaseStockOutQty"]) == 0)
        {
            e.SourceActiveRow["DeliveryStatus"] = "A";
        }
        else
        {
            e.SourceActiveRow["DeliveryStatus"] = "B";
        }
    }
}
```

### 3.8 BeforeCheckHighLimit

**触发时机**：每个源单行反写完毕后，进行超额检查之前

**应用场景**：干预源单超额检查，初始化重要属性，或直接取消超额检查

**关键属性**：

- `SourceBusinessInfo`：上游单据元数据信息
- `Rule`：本次反写采用的反写规则
- `Cancel`：是否取消超额检查
- `MustCheck`：是否必须检查
- `OnlyCheckAtLastTime`：是否最后一次反写才做超额检查
- `ExcessCheckFormula`：超额检查自定义前置条件

**示例代码**：

```csharp
public override void BeforeCheckHighLimit(BeforeCheckHighLimitEventArgs e)
{
    if (_thisIsMyRule == true)
    {
        // 根据系统参数决定是否进行超额检查
        bool allowExcess = GetSystemParamAllowExcess();
        if (allowExcess)
        {
            e.Cancel = true; // 取消超额检查
        }
    }
}
```

### 3.9 AfterCheckHighLimit

**触发时机**：每个源单行反写完毕后，超额检查之后

**应用场景**：干预源单超额检查后，是否抛出超额检查错误，以及自定义超额检查错误提示语

**关键属性**：

- `SourceBusinessInfo`：上游单据元数据信息
- `Rule`：本次反写采用的反写规则
- `IsExcessHighLimit`：是否超额提示
- `ErrorMessage`：自定义超额提示信息

**示例代码**：

```csharp
public override void AfterCheckHighLimit(AfterCheckHighLimitEventArgs e)
{
    if (_thisIsMyRule == true)
    {
        // 自定义超额提示信息
        if (e.IsExcessHighLimit)
        {
            e.ErrorMessage = "反写数量超过源单数量，请检查！";
        }
    }
}
```

### 3.10 BeforeSaveWriteBackData

**触发时机**：保存源单数据前

**应用场景**：保存源单数据前，干预源单整体数据包，处理相关业务

**关键属性**：

- `SourceBusinessInfo`：上游单据元数据信息
- `SourceDataEntitySet`：上游单据数据包扁平化管理对象（源单整体数据包，以单据实体对象为管理维度）

**示例代码**：

```csharp
public override void BeforeSaveWriteBackData(BeforeSaveWriteBackDataEventArgs e)
{
    if (_thisIsMyRule == false) return;
    
    // 处理源单数据包
    foreach (var item in e.SourceDataEntitySet)
    {
        // 处理每个源单的数据
    }
}
```

### 3.11 AfterSaveWriteBackData

**触发时机**：源单数据保存后

**应用场景**：保存源单数据后，处理其他相关业务逻辑

**关键属性**：

- `SourceBusinessInfo`：上游单据元数据信息
- `SourceDataEntitySet`：上游单据数据包扁平化管理对象

**示例代码**：

```csharp
public override void AfterSaveWriteBackData(AfterSaveWriteBackDataEventArgs e)
{
    if (_thisIsMyRule == false) return;
    
    // 处理保存后的业务逻辑
    // 例如：发送通知、记录日志等
}
```

**示例代码**：

```csharp
public override void FinishWriteBack(FinishWriteBackEventArgs e)

    // 处理所有反写完成后的逻辑
```

#### 4.1.1 事件触发顺序示例

以下是一个演示事件触发顺序的示例代码，展示了如何在反写插件中处理事件顺序：

```csharp
using System;
using System.Collections.Generic;
using System.Linq;
using System.Text;
using System.Threading.Tasks;
using System.ComponentModel;
using Kingdee.BOS;
using Kingdee.BOS.Util;
using Kingdee.BOS.Core;
using Kingdee.BOS.Core.BusinessFlow;
using Kingdee.BOS.Core.BusinessFlow.PlugIn;
using Kingdee.BOS.Core.BusinessFlow.PlugIn.Args;

namespace SamplePlugIn.WriteBackPlugIn
{
    /// <summary>
    /// 按顺序输出反写插件的事件
    /// </summary>
    [Description("按顺序输出反写插件的事件")]
    public class WritebackEventSeq : AbstractBusinessFlowServicePlugIn
    {
        /// <summary>
        /// 记录业务流程跟踪信息之前，触发本事件；
        /// 此时，还未分析本单的关联信息
        /// </summary>
        /// <param name="e"></param>
        /// <remarks>
        /// 可以在此事件中，强制要求不创建业务流程跟踪数据，不反写
        /// </remarks>
        public override void BeforeTrackBusinessFlow(BeforeTrackBusinessFlowEventArgs e)
        {
            base.BeforeTrackBusinessFlow(e);
            this.PrintEventName("BeforeTrackBusinessFlow");
        }

        /// <summary>
        /// 逐行循环，分析单据体每行的关联数据之前，触发本事件
        /// </summary>
        /// <param name="e"></param>
        /// <remarks>
        /// 可以在此事件中，强制要求不分析当前单据体行的关联关系，从而不创建此行的业务流程跟踪数据，不反写
        /// </remarks>
        public override void BeforeCreateArticulationRow(BeforeCreateArticulationRowEventArgs e)
        {
            base.BeforeCreateArticulationRow(e);
            this.PrintEventName("BeforeCreateArticulationRow");
        }

        /// <summary>
        /// 当前是否为本插件关注的反写规则?
        /// </summary>
        /// <remarks>
        /// 从BeforeWriteBack事件开始，事件基于反写规则，循环触发；
        /// 为避免重复反写，需要判断当前反写规则
        /// </remarks>
        private bool _thisIsMyRule = false;

        /// <summary>
        /// 系统在循环中，逐一执行反写规则之前，触发本事件；
        /// </summary>
        /// <param name="e"></param>
        public override void BeforeWriteBack(BeforeWriteBackEventArgs e)
        {
            base.BeforeWriteBack(e);
            this.PrintEventName("BeforeWriteBack");
        }

        // 其他事件的实现...

        private void PrintEventName(string eventName)
        {
            Console.WriteLine($"[{DateTime.Now.ToString("yyyy-MM-dd HH:mm:ss.fff")}] 触发事件: {eventName}");
        }
    }
}
```

#### 4.1.2 反写采购订单交货计划示例

以下是一个反写采购订单交货计划的示例代码：

```csharp

using System.Collections.Generic;
using System.ComponentModel;
using System.Linq;
using System.Text;
using Kingdee.BOS.Core.BusinessFlow.PlugIn;
using Kingdee.BOS.Core.Metadata.FieldElement;
using Kingdee.BOS.Core.Metadata;

using Kingdee.BOS.Util;

using Kingdee.K3.BD.Contracts;
using Kingdee.K3.Core.BD;

{
    [Description("收料单、入库单共用反写订单交货计划的插件 V1.0正式版添加")]
    public class PODeliveryPlanWriteBack : AbstractBusinessFlowServicePlugIn
    {
        /// <summary>
        /// 当前是否为本插件关注的反写规则?
        /// </summary>
        private bool _thisIsMyRule = false;

        /// <summary>
        /// 循环中，逐一执行反写规则之前，触发本事件；
        /// </summary>
        /// <param name="e"></param>
        /// <remarks>
        /// 判断当前规则，是否为本插件需关注的规则

        public override void BeforeWriteBack(BeforeWriteBackEventArgs e)
        {
            string srcFormId = e.SourceBusinessInfo.GetForm().Id;
            if (this.WriteBackDeliPlanCondition(srcFormId, this.OperationNumber))
            {
                _thisIsMyRule = true;
            }
        }

        public override void AfterCustomReadFields(AfterCustomReadFieldsEventArgs e)
        {
            if (_thisIsMyRule == true)
            {
                e.AddFieldKey("FBillTypeID");
                this.AddDeliveryPlanField(e);
            }

            e.AddFieldKey("FPlanQty");//计划数量（交货计划）
            // 添加其他需要的字段...
        }

        private bool WriteBackDeliPlanCondition(string srcFormId, string operationNumber)
        {
            // 判断是否满足反写交货计划的条件
            // 例如：判断源单类型、操作类型等
            return true;
        }
    }
```
