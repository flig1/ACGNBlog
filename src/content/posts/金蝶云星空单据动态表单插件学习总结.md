# 金蝶云星空单据动态表单插件学习总结

## 1. 引言

在金蝶云星空（Kingdee Cloud Starry Sky）的BOS（Business Operation Studio）二次开发体系中，动态表单插件是最核心、最常用的开发方式之一。动态表单插件作为单据、基础资料、列表、过滤界面等插件的基类，提供了统一的接口，通过这些接口可以对表单编辑样式、列表样式、操作、model数据等进行全面控制。

## 2. 核心概念

### 2.1 动态表单插件架构

动态表单插件采用了经典的"模型-视图"分离设计模式：

- **模型层（Model）**：由IDynamicFormModel接口实现，负责数据管理、业务逻辑处理和状态维护
- **视图层（View）**：由IDynamicFormView接口实现，负责界面展示、用户交互和控件管理
- **插件层**：作为连接模型和视图的桥梁，通过事件系统响应各种用户操作和系统事件

### 2.2 插件基类

在动态表单插件开发中，主要使用以下基类：

| 基类名称 | 描述 | 适用场景 |
|---------|------|----------|
| `AbstractDynamicFormPlugIn` | 动态表单插件基类 | 适用于各种动态表单 |
| `AbstractBillPlugIn` | 单据维护插件基类 | 继承自AbstractDynamicFormPlugIn，适用于单据维护 |
| `AbstractListPlugIn` | 列表插件基类 | 继承自AbstractDynamicFormPlugIn，适用于列表界面 |

### 2.3 插件生命周期

动态表单插件的生命周期从请求加载到关闭，主要经历以下阶段：

1. **加载前阶段**
   - PreOpenForm：加载页面之前触发，可用于取消页面展示或设置打开参数

2. **初始化阶段**
   - OnInitializeService：初始化服务对象
   - OnSetBusinessInfo：设置业务元数据
   - OnSetLayoutInfo：设置布局元数据
   - OnCreateDataBinder：创建数据绑定器
   - OnInitialize：页面初始化
   - OnBillInitialize：单据初始化（仅单据插件）

3. **数据创建阶段**
   - CreateNewData：创建新数据
   - BeforeCreateNewEntryRow：创建分录行前
   - AfterCreateNewEntryRow：创建分录行后
   - AfterCreateNewData：数据创建后
   - AfterCreateModelData：模型数据创建后

4. **数据绑定阶段**
   - OnLoad：页面加载
   - BeforeBindData：绑定数据前
   - AfterBindData：绑定数据后

5. **交互阶段**
   - BarItemClick：主菜单点击
   - AfterBarItemClick：主菜单点击后
   - ButtonClick：按钮点击
   - AfterButtonClick：按钮点击后
   - EntityRowDoubleClick：分录行双击
   - AfterDeleteRow：删除行后

6. **关闭阶段**
   - BeforeClosed：关闭前

## 3. 公共属性详解

### 3.1 Context

**描述**：当前登录系统上下文全局信息，如：当前系统语言、用户、组织、数据库类型、客户端连接类型、数据库连接信息等。

**用途**：
- 获取当前用户信息：`this.Context.UserId`、`this.Context.UserName`
- 获取当前组织信息：`this.Context.CurrentOrganizationInfo`
- 获取客户端类型：`this.Context.ClientType`
- 获取数据库类型：`this.Context.DatabaseType`
- 作为服务调用的必要参数

### 3.2 Model

**描述**：动态表单的数据模型接口，负责数据管理、业务逻辑处理等核心功能。

**用途**：
- 数据操作：`GetValue`、`SetValue`
- 单据体操作：`CreateNewEntryRow`、`DeleteEntryRow`
- 数据状态管理：`BeginIniti`、`EndIniti`、`DataChanged`
- 元数据访问：`BillBusinessInfo`、`BusinessInfo`

### 3.3 View

**描述**：动态表单的视图接口，负责界面展示、用户交互和控件管理等功能。

**用途**：
- 控件操作：`GetControl`、`GetFieldEditor`
- 菜单操作：`GetMainBarItem`、`GetBarItem`
- 界面控制：`Close`、`ShowMessage`
- 子页面交互：`ShowForm`、`ReturnToParentWindow`
- 模型访问：`View.Model`

## 4. 事件系统详解

### 4.1 加载前事件

#### PreOpenForm

**触发时机**：加载页面之前

**应用场景**：
- 判断当前页面是否符合展开的特殊业务条件，不符合则取消打开
- 指定表单视图、表单标题等动态表单打开参数信息
- 根据自定义参数设置表单状态

**示例代码**：

```csharp
public override void PreOpenForm(PreOpenFormEventArgs e)
{
    // 根据自定义参数设置表单状态
    object openType = e.OpenParameter.GetCustomParameter("OperationStatus");
    if (openType != null && openType.ToString().Equals("New", StringComparison.OrdinalIgnoreCase))
    {
        e.OpenParameter.Status = OperationStatus.ADDNEW;
    }
    else if (openType != null && openType.ToString().Equals("Edit", StringComparison.OrdinalIgnoreCase))
    {
        e.OpenParameter.Status = OperationStatus.EDIT;
    }
}
```

### 4.2 初始化事件

#### OnInitialize

**触发时机**：请求加载页面时触发，此时Model还没初始化，View已基本完成初始化

**应用场景**：
- 根据View打开参数和View的信息，初始化当前插件的一些全局属性
- 修改当前页面的控件属性值，如控件大小、字段标题、表单标题等
- 动态修改字段标题

**示例代码**：

```csharp
public override void OnInitialize(InitializeEventArgs e)
{
    // 从自定义参数中获取"是否含税"
    bool includeTax = Convert.ToBoolean(e.Paramter.GetCustomParameter("IncludedTax"));
    
    // 根据参数动态设置字段标题
    if (includeTax)
    {
        this.View.GetControl("FEndAmount").Text = "行折后含税金额";
    }
    else
    {
        this.View.GetControl("FEndAmount").Text = "行折后金额";
    }
}
```

#### OnSetBusinessInfo

**触发时机**：在请求加载页面之后，渲染界面控件之前触发

**应用场景**：
- 动态调整界面，增删字段
- 修改单据的逻辑元模型
- 动态生成尺码列等特殊字段

**示例代码**：

```csharp
public override void OnSetBusinessInfo(SetBusinessInfoArgs e)
{
    // 创建当前单据元数据副本
    FormMetadata currmetadata = (FormMetadata)ObjectUtils.CreateCopy(this.View.OpenParameter.FormMetaData);
    var currBusinessInfo = currmetadata.BusinessInfo;
    
    // 动态添加字段
    Field newField = new Field();
    newField.Key = "FNewField";
    newField.Name = new LocaleValue("新字段");
    // 设置其他属性...
    
    // 添加到业务元数据
    currBusinessInfo.Add(newField);
}
```

### 4.3 数据创建事件

#### CreateNewData

**触发时机**：View已完成初始化，开始进入Model数据对象初始化

**应用场景**：
- 插件自定义Model.DataObject数据包
- 构建自定义默认值
- 初始化复杂数据结构

**示例代码**：

```csharp
public override void CreateNewData(BizDataEventArgs e)
{
    // 创建本界面需要的数据对象
    e.BizDataObject = new DynamicObject(this.View.OpenParameter.FormMetaData.BusinessInfo.GetDynamicObjectType());
    
    // 给字段设置默认值
    BusinessInfo info = this.View.OpenParameter.FormMetaData.BusinessInfo;
    Field dateField = info.GetField("FDate");
    dateField.DynamicProperty.SetValue(e.BizDataObject, DateTime.Now);
}
```

#### AfterCreateNewData

**触发时机**：新增单据场景下，Model数据包创建之后，绑定数据之前触发

**应用场景**：
- 自定义设置字段默认值
- 根据业务规则初始化数据
- 加载关联数据

**示例代码**：

```csharp
public override void AfterCreateNewData(EventArgs e)
{
    // 获取当前组织邮件信息
    OQLFilter ofilter = new OQLFilter();
    ofilter.Add(new OQLFilterHeadEntityItem { FilterString = string.Format(" FORGID ={0} ", this.Model.Context.CurrentOrganizationInfo.ID) });
    
    DynamicObject[] obj = BusinessDataServiceHelper.Load(this.View.Context, "BAS_MAILDEFAULTSET", null, ofilter);
    if (obj != null && obj.Count() > 0)
    {
        DynamicObject defaultSet = obj[0];
        // 设置邮件相关字段默认值
        this.View.Model.SetValue("FMessageType", defaultSet["FMessageType"]);
        this.View.Model.SetValue("FServer", defaultSet["FOutgoingMailServer"]);
        this.View.Model.SetValue("FSMTPPort", defaultSet["FSMTPPort"]);
    }
}
```

### 4.4 数据绑定事件

#### AfterBindData

**触发时机**：控件绑定数据之后触发

**应用场景**：
- 根据业务条件设置控件的可见性、可用性
- 设置控件样式，如背景颜色、字体等
- 初始化控件状态

**示例代码**：

```csharp
public override void AfterBindData(EventArgs e)
{
    // 根据类型设置字段可见性
    if (_modelTypeId == ElementType.ELEMENTTYPE_BASE.ToString())
    {
        // 基础资料隐藏字段参数页签
        this.View.StyleManager.SetVisible("FTab_Field", null, false);
    }
    else if (_modelTypeId == ElementType.ELEMENTTYPE_BILL.ToString())
    {
        // 单据判断是否包含单据类型字段
        if (this._metaData.GetLayoutInfo().GetFieldAppearances().Any(f => f is BillTypeFieldAppearance))
        {
            this.View.StyleManager.SetVisible("FTab_Field", null, true);
        }
    }
}
```

### 4.5 交互事件

#### BarItemClick

**触发时机**：主菜单单击时触发

**应用场景**：
- 权限验证：检查用户是否有操作权限
- 数据检查：验证数据完整性和合法性
- 自定义处理逻辑：取消平台内置功能，实现自定义逻辑

**示例代码**：

```csharp
public override void BarItemClick(BarItemClickEventArgs e)
{
    switch (e.BarItemKey.ToUpperInvariant())
    {
        case "TBPAYSEARCH":
            // 检查付款单查看权限
            PermissionAuthResult iResult = PermissionServiceHelper.FuncPermissionAuth(this.Context, 
                new BusinessObject() { Id = "AP_PAYBILL" }, PermissionConst.View);
            if (!iResult.Passed)
            {
                this.View.ShowMessage("没有付款单的查看权限，不能查询");
                e.Cancel = true;
                return;
            }
            // 展示付款单列表
            this.ShowPayList();
            break;
        default:
            break;
    }
}
```

#### ButtonClick

**触发时机**：按钮点击时触发

**应用场景**：
- 执行自定义业务逻辑
- 弹出子页面
- 数据验证和处理

**示例代码**：

```csharp
public override void ButtonClick(ButtonClickEventArgs e)
{
    switch (e.Key.ToUpper())
    {
        case "FBTNCONFIRM":
            // 验证日期字段
            object dtObj = this.View.Model.GetValue("FDate");
            if (dtObj == null)
            {
                this.View.ShowMessage("请选择日期");
                return;
            }
            // 返回数据给父页面
            DateTime dt = (DateTime)dtObj;
            this.View.ReturnToParentWindow(dt);
            this.View.Close();
            break;
        case "FBTNCANCEL":
            this.View.Close();
            break;
        default:
            break;
    }
}
```

### 4.6 关闭事件

#### BeforeClosed

**触发时机**：页面关闭之前触发

**应用场景**：
- 数据改动检查：提示用户保存未保存的数据
- 多表单交互：更新父表单内容
- 资源释放：清理临时资源

**示例代码**：

```csharp
public override void BeforeClosed(BeforeClosedEventArgs e)
{
    // 检查数据是否有改动
    if (this.Model.DataChanged)
    {
        e.Cancel = true;
        this.View.ShowMessage("数据已修改，是否保存？", MessageBoxOptions.YesNoCancel, (result) =>
        {
            if (result == MessageBoxResult.Yes)
            {
                // 保存数据
                this.View.Save();
                this.View.Close();
            }
            else if (result == MessageBoxResult.No)
            {
                // 不保存，直接关闭
                this.View.Close();
            }
        });
    }
}
```

## 5. 典型案例分析

### 5.1 案例一：动态修改字段标题

**需求背景**：在打开折扣明细表时，判断折后金额是否含税，如果是含税金额，则"折扣金额"字段的标题显示为"行折扣含税金额"，否则标题显示为"行折扣金额"。

**实现方案**：
1. 在OnInitialize事件中从自定义参数获取"是否含税"参数
2. 根据参数值动态设置折扣金额字段的标题

**核心代码**：

```csharp
public override void OnInitialize(InitializeEventArgs e)
{
    // 从自定义参数中获取"是否含税"
    bool includeTax = Convert.ToBoolean(e.Paramter.GetCustomParameter("IncludedTax"));
    
    // 根据参数值动态设置字段标题
    if (includeTax)
    {
        this.View.GetControl("FEndAmount").Text = "行折后含税金额";
    }
    else
    {
        this.View.GetControl("FEndAmount").Text = "行折后金额";
    }
}
```

**添加自定义参数方法**：

```csharp
// 点击销售订单、销售出库单、销售退货单等表体折扣明细按钮触发打开折扣明细表
DynamicFormShowParameter param = new DynamicFormShowParameter();
// 折扣明细表FormId
param.FormId = "SAL_DISCOUNTDETAIL";
// 新增"是否含税"参数
param.CustomParams.Add("IncludedTax", "true");
// 打开折扣明细表
this.View.ShowForm(param);
```

### 5.2 案例二：根据供应商取价

**需求背景**：入库单填写供应商之后，需要根据供应商价格表自动填写价格到单据上。

**实现方案**：
1. 捕获供应商字段的DataChanged事件
2. 在事件处理中，根据供应商ID查询价格表
3. 使用BeginIniti/EndIniti包装字段赋值操作，避免触发值改变事件
4. 设置价格字段值

**核心代码**：

```csharp
public override void DataChanged(DataChangedEventArgs e)
{
    base.DataChanged(e);
    
    if (e.Field.Key == "FSupplierId")
    {
        // 获取供应商ID
        var supplierId = this.Model.GetValue("FSupplierId");
        if (supplierId != null)
        {
            // 查询供应商价格
            var price = GetSupplierPrice(supplierId.ToString());
            
            // 批量设置价格字段，避免触发值改变事件
            this.Model.BeginIniti();
            try
            {
                this.Model.SetValue("FPrice", price, e.Row);
                this.Model.SetValue("FTaxPrice", price * 1.17, e.Row);
            }
            finally
            {
                this.Model.EndIniti();
            }
        }
    }
}
```

### 5.3 案例三：控制菜单按钮状态

**需求背景**：根据单据状态控制菜单按钮的可用性。

**实现方案**：
1. 在AfterBindData事件中获取单据状态
2. 根据单据状态设置菜单按钮的可用性
3. 对于查看状态，禁用编辑相关的按钮

**核心代码**：

```csharp
public override void AfterBindData(EventArgs e)
{
    base.AfterBindData(e);
    
    // 获取单据状态
    string status = Convert.ToString(this.Model.GetValue("FDocumentStatus"));
    
    // 根据状态设置菜单按钮
    bool isEditMode = (status == "A" || status == "E");
    
    // 设置保存按钮
    this.View.GetMainBarItem("tbSave").Enabled = isEditMode;
    
    // 设置提交按钮
    this.View.GetMainBarItem("tbSubmit").Enabled = isEditMode;
    
    // 设置审核按钮
    this.View.GetMainBarItem("tbAudit").Enabled = (status == "S");
}
```

### 5.4 案例四：批量创建单据体行

**需求背景**：根据评估模型批量创建信用评估单据体行。

**实现方案**：
1. 在AfterCreateNewData事件中加载评估模型数据
2. 使用BatchCreateNewEntryRow批量创建单据体行
3. 逐行设置评估模型数据

**核心代码**：

```csharp
public override void AfterCreateNewData(EventArgs e)
{
    // 获取评估模型数据
    var assessmentItems = GetAssessmentModelItems();
    
    // 批量创建单据体行
    this.Model.BatchCreateNewEntryRow("FEntity", assessmentItems.Count);
    
    // 逐行设置数据
    for (int i = 0; i < assessmentItems.Count; i++)
    {
        var item = assessmentItems[i];
        this.Model.SetValue("FItemName", item.Name, i);
        this.Model.SetValue("FItemWeight", item.Weight, i);
        this.Model.SetValue("FItemScore", item.DefaultScore, i);
    }
}
```

## 6. 最佳实践

### 6.1 代码结构最佳实践

1. **分层设计**：遵循模型-视图分离原则，业务逻辑放在Model层处理，UI操作放在View层处理
2. **事件处理**：合理使用插件事件，避免在一个事件中处理过多逻辑
3. **异常处理**：使用try-catch-finally结构，确保资源正确释放
4. **代码复用**：将通用逻辑抽象为方法或基类，提高代码复用性
5. **命名规范**：使用清晰、一致的命名规范，提高代码可读性

### 6.2 性能优化

1. **批量操作**：对于大量数据操作，使用批量方法如BatchCreateNewEntryRow
2. **减少事件触发**：使用BeginIniti/EndIniti包装批量字段修改，减少事件触发
3. **延迟加载**：对于非必要数据，采用延迟加载策略
4. **缓存使用**：合理使用Session缓存临时数据，减少重复计算
5. **数据库操作**：优化查询语句，使用参数化查询，减少数据库访问次数

### 6.3 常见问题与解决方案

| 问题 | 解决方案 |
|------|----------|
| 值改变事件循环触发 | 使用BeginIniti/EndIniti包装字段修改操作 |
| 控件状态不更新 | 使用View.UpdateView()方法强制刷新控件 |
| 数据验证失败 | 在BeforeSave事件中进行数据验证，提供明确的错误提示 |
| 性能问题 | 优化代码，减少不必要的计算和数据库操作 |
| 权限问题 | 在操作前使用PermissionServiceHelper进行权限验证 |

### 6.4 调试技巧

1. **日志输出**：使用Logger输出关键信息，便于调试
2. **断点设置**：在关键位置设置断点，观察变量值变化
3. **异常捕获**：捕获并记录异常信息，便于排查问题
4. **分步测试**：将复杂逻辑拆分为多个步骤，分步测试
5. **参数检查**：使用断言或条件判断检查参数合法性
6. **性能分析**：使用性能分析工具找出性能瓶颈

        }
