# 账表服务取数插件复习文档

## 1. 引言

### 1.1 术语定义

| 术语 | 解释 |
|------|------|
| 账表服务取数插件 | 负责组装账表取数 SQL 指令，将取数结果返回给平台账表引擎的服务端插件 |
| 简单账表 | 直接显示所有数据的账表类型 |
| 树形账表 | 通过树节点切换账表内容的账表类型 |
| 分页账表 | 通过导航按钮切换账表内容的账表类型 |
| 简单 SQL 账表 | 直接通过 SQL 取数的账表类型，无需服务取数插件 |
| 临时表 | 用于存储账表取数结果的临时数据库表 |

## 2. 核心概念

### 2.1 账表服务取数插件概述
账表的服务端取数插件是通过插件组装账表取数 SQL 指令，把取数结果返回给平台账表引擎，平台将取数结果绑定到账表页面的过程。简单来说，平台在账表开发过程中，只负责把插件取到的账表数据绑定到设计好的账表模型上，取数逻辑由账表服务端插件完成。

### 2.2 账表类型

| 账表类型 | 特点 | 实现方式 |
|---------|------|----------|
| 简单账表 | 直接显示所有数据 | 实现基本事件即可 |
| 分页账表 | 通过导航按钮切换账表内容 | 需实现 GetList 方法 |
| 树形账表 | 通过树节点切换账表内容 | 需实现 GetTreeNodes 方法 |
| 简单 SQL 账表 | 直接通过 SQL 取数 | 无需服务取数插件 |

### 2.3 开发流程

1. 创建插件类库工程
2. 引用 BOS 平台组件（website\bin 目录下）
3. 修改插件类库编译输出路径为 website\bin
4. 修改类文件继承基类 SysReportBaseService
5. 实现必要的事件方法
6. 在 BOS 设计器中配置账表服务插件

## 3. 插件开发基础

### 3.1 插件类结构

```csharp
using Kingdee.BOS.Contracts.Report;
using Kingdee.BOS.Core.Report;
using Kingdee.BOS;

namespace YourNamespace
{
    public class YourReportPlugin : SysReportBaseService
    {
        // 实现必要的事件方法
    }
}
```

### 3.2 必要实现的事件

1. Initialize - 初始化账表属性
2. BuilderSelectFieldSQL - 构建查询字段 SQL
3. BuilderFromWhereSQL - 构建 FROM 和 WHERE 子句
4. BuilderReportSqlAndTempTable - 构建完整 SQL 并填充临时表
5. GetReportTitles - 获取账表表头信息
6. GetReportHeaders - 获取账表列头信息
7. GetSummaryColumnInfo - 获取分组汇总字段信息

### 3.3 临时表管理
- 临时表用于存储账表取数结果
- 插件应在 CloseReport 事件中清理临时表资源
- 平台会自动管理部分临时表，但自定义临时表需要手动清理

## 4. 公共属性详解

### 4.1 BusinessInfo
- 账表模型的元数据描述信息
- 用于获取账表模型的结构信息

### 4.2 Context
- 当前登录系统的上下文信息
- 包含数据库连接信息、当前登录操作员信息等
- 用于执行 SQL 语句、获取系统参数等

### 4.3 ReportProperty
- 账表属性，包含账表开发过程中的全局信息
- 重要属性：
  | 属性名 | 描述 |
  |--------|------|
  | ReportType | 账表类型（默认是简单账表） |
  | IsGroupSummary | 是否支持分组汇总 |
  | IsUIDesignerColumns | 账表列头是否是通过 BOSIDE 设计 |
  | SimpleAllCols | 是否锁定账表表格列 |
  | DecimalControlFieldList | 精度控制字段信息 |
  | DspInsteadColumnsInfo | 列表格式化列，指示 Key 列被 Value 列内容替代 |
  | GroupSummaryInfoData | 分组汇总信息 |

### 4.4 ReportId
- 当前账表模型唯一标识
- 用于识别账表模型

### 4.5 ReportTitles
- 账表表头字段信息
- 用于存储和管理账表表头数据

### 4.6 ReportHeader
- 账表列头信息
- 用于存储和管理账表列头数据

### 4.7 TempTableNameList
- 临时表列表
- 用于管理账表使用的临时表

### 4.8 SummarySpecialFields
- 汇总字段信息
- 用于存储和管理账表汇总字段

## 5. 事件系统详解

### 5.1 Initialize
- **触发时机**：账表 View 初始化，开始初始化账表服务取数插件代理对象时
- **应用场景**：对 ReportProperty 做进一步初始化
- **示例代码**：

  ```csharp
  public override void Initialize()
  {
      base.Initialize();
      this.ReportProperty.ReportType = ReportType.REPORTTYPE_NORMAL;
      this.ReportProperty.ReportName = "销售订单执行汇总表";
      this.ReportProperty.IsGroupSummary = true;
      this.ReportProperty.IsUIDesignerColumns = true;
      // 配置替代显示列
      this.ReportProperty.DspInsteadColumnsInfo.DefaultDspInsteadColumns.Add("FSALEORGID", "FSALEORGNAME");
  }
  ```

### 5.2 BuilderReportSqlAndTempTable
- **触发时机**：正式进入账表取数 SQL 拼接并取数，把账表取数结果放到临时表中
- **应用场景**：构建完整的 SQL 查询并执行，将结果填充到临时表
- **示例代码**：

  ```csharp
  public override void BuilderReportSqlAndTempTable(IRptParams filter, string tableName)
  {
      string whereSql = GetWhereSql(filter);
      string sql = $"SELECT * FROM T_SAL_ORDER WHERE {whereSql}";
      string insertSql = $"INSERT INTO {tableName} SELECT * FROM ({sql}) t";
      DBUtils.Execute(this.Context, insertSql);
  }
  ```

### 5.3 BuilderSelectFieldSQL
- **触发时机**：当 IsCreateTempTableByPlugin = false 时，开始构建账表取数 SQL 指令
- **应用场景**：构建 SQL 的 SELECT 部分
- **示例代码**：

  ```csharp
  protected override string BuilderSelectFieldSQL(IRptParams filter)
  {
      return @"select seq.FMaterialID,seq.FStockOrgId,FStockID,FCargoOwnerId as FOwnerID,max(FBillCheckResult) as Result,
               seq.FBillId as FSrcID,FBillEntryId as FSrcEntryID,FAcctgSysId as FacctSysID,FAcctgOrgId as FAcctOrgID,FYear,FPeriod,seq.FQty";
  }
  ```

### 5.4 BuilderFromWhereSQL
- **触发时机**：当 IsCreateTempTableByPlugin = false 时，开始构建账表取数 SQL 指令
- **应用场景**：构建 SQL 的 FROM 和 WHERE 部分
- **示例代码**：

  ```csharp
  protected override string BuilderFromWhereSQL(IRptParams filter)
  {
      StringBuilder sb = new StringBuilder();
      DynamicObject para = filter.FilterParameter.CustomFilter;
      int year = Convert.ToInt32(para["Year"]);
      int period = Convert.ToInt32(para["Period"]);
      
      sb.AppendFormat(" from {0} OutAcct left join {1} Chk", "T_HS_OUTACCTG", "T_HS_OUTACCTGCHECK");
      sb.AppendFormat(" on Chk.FID = OutAcct.FID inner join {0} process on process.FID = OutAcct.FID", "T_HS_AcctgProcess");
      sb.AppendFormat(" where OutAcct.FPeriod = {0} and OutAcct.FYear = {1}", period, year);
      
      return sb.ToString();
  }
  ```

### 5.5 GetReportHeaders
- **触发时机**：准备账表列头信息
- **应用场景**：如果账表模型在设计时没有配置账表单据体字段信息，则通过此方法设置
- **示例代码**：

  ```csharp
  public override ReportHeader GetReportHeaders(IRptParams filter)
  {
      ReportHeader header = new ReportHeader();
      header.AddChild("FContactUnit", "往来单位");
      header.AddChild("FCurrencyName", "币别");
      header.AddChild("FDate", "业务日期");
      return header;
  }
  ```

### 5.6 GetReportTitles
- **触发时机**：完成账表数据取数并赋值给临时表，完成临时表索引创建，开始准备账表表头信息
- **应用场景**：根据账表过滤方案准备账表的表头信息
- **示例代码**：

  ```csharp
  public override ReportTitles GetReportTitles(IRptParams filter)
  {
      ReportTitles rptTitl = new ReportTitles();
      DynamicObject dyFilter = filter.FilterParameter.CustomFilter;
      
      if (dyFilter != null)
      {
          if (filterOrgList.Trim().Length > 0)
              rptTitl.AddTitle("FSaleOrgListTitle", this.OrgNameList(filterOrgList));
          else
              rptTitl.AddTitle("FSaleOrgListTitle", "");
      }
      
      return rptTitl;
  }
  ```

### 5.7 GetSummaryColumnInfo
- **触发时机**：获取账表分组汇总字段信息、汇总类型
- **应用场景**：配置账表分组汇总字段和汇总类型
- **示例代码**：

  ```csharp
  public override List<SummaryField> GetSummaryColumnInfo(IRptParams filter)
  {
      List<SummaryField> list = new List<SummaryField>();
      list.Add(new SummaryField("FSOAMOUNT", Kingdee.BOS.Core.Enums.BOSEnums.Enu_SummaryType.SUM));
      list.Add(new SummaryField("FSAMOUNT", Kingdee.BOS.Core.Enums.BOSEnums.Enu_SummaryType.SUM));
      list.Add(new SummaryField("FALREADYAMOUNT", Kingdee.BOS.Core.Enums.BOSEnums.Enu_SummaryType.SUM));
      return list;
  }
  ```

### 5.8 CloseReport
- **触发时机**：关闭账表页面时
- **应用场景**：清除账表插件使用到的临时表资源等业务操作
- **示例代码**：

  ```csharp
  public override void CloseReport()
  {
      if (tempTables.Count > 0)
      {
          var service = Kingdee.K3.SCM.App.ServiceHelper.GetService<ITemporaryTableService>();
          service.DropTable(this.Context, new HashSet<string>(tempTables));
      }
  }
  ```

## 7. 典型案例分析

### 7.1 销售订单执行汇总表
- **需求背景**：销售订单执行汇总表需要显示销售订单的执行情况，支持分组汇总
- **实现要点**：
  1. 在 Initialize 方法中设置账表属性
  2. 在 BuilderReportSqlAndTempTable 方法中构建 SQL 并填充临时表
  3. 在 GetSummaryColumnInfo 方法中配置汇总字段
  4. 在 GetReportTitles 方法中构建表头信息

### 7.2 应付款账龄分析表
- **需求背景**：应付款账龄分析表需要根据账龄区间显示应付款情况
- **实现要点**：
  1. 在 GetReportHeaders 方法中动态构建列头
  2. 根据账龄区间生成不同的列
  3. 在 BuilderReportSqlAndTempTable 方法中计算账龄

### 7.3 供应商供货汇总表
- **需求背景**：供应商供货汇总表需要显示供应商的供货情况，支持辅助属性显示
- **实现要点**：
  1. 在 GetReportData 方法中更新辅助属性的值
  2. 在 CloseReport 方法中清理临时表

## 8. 最佳实践

### 8.1 性能优化
- **SQL 优化**：使用索引字段，避免全表扫描
- **临时表管理**：及时清理临时表，避免资源泄露
- **数据过滤**：在 SQL 层面进行数据过滤，减少数据传输量
- **分页处理**：对于大数据量的账表，使用分页账表类型

### 8.2 代码规范
- **命名规范**：使用有意义的类名和方法名
- **注释规范**：为关键方法和复杂逻辑添加注释
- **异常处理**：捕获并处理可能的异常
- **代码结构**：保持代码结构清晰，逻辑分明

### 8.3 常见问题及解决方案

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 账表数据为空 | SQL 语句错误或过滤条件过于严格 | 检查 SQL 语句，调整过滤条件 |
| 分组汇总不正确 | 汇总字段配置错误 | 检查 GetSummaryColumnInfo 方法中的汇总字段配置 |
| 临时表清理失败 | 临时表名称记录不完整 | 确保所有临时表都添加到 TempTableNameList 中 |
| 树形账表节点不显示 | GetTreeNodes 方法实现错误 | 检查 GetTreeNodes 方法的实现逻辑 |
| 分页账表导航不工作 | GetList 方法实现错误 | 检查 GetList 方法的实现逻辑 |
