# 单据维护插件复习文档

## 1. 引言

### 1.1 术语定义

| 术语         | 解释                                                   |
| ------------ | ------------------------------------------------------ |
| 单据维护插件 | 继承自 AbstractBillPlugIn 的插件，用于扩展单据维护功能 |
| 视图层       | 负责界面显示和用户交互的插件层                         |
| 模型层       | 负责数据处理和业务逻辑的插件层                         |
| 事件         | 插件中用于响应特定操作的方法                           |
| 生命周期     | 单据从创建到销毁的整个过程                             |
| 下推         | 从源单据生成目标单据的操作                             |
| 上查/下查    | 查看单据上下游关联关系的操作                           |

## 2. 核心概念

### 2.1 单据维护插件概述

单据维护插件是金蝶云星空 BOS 平台中用于扩展单据维护功能的插件类型，继承自 AbstractBillPlugIn 基类。它实现了 IBillViewPlugIn 和 IBillModelPlugIn 两个接口，分别负责视图层和模型层的功能。

### 2.2 插件架构（模型-视图分离）

单据维护插件采用模型-视图分离的设计架构：

- **模型层（Model）**：负责数据处理、业务逻辑和数据访问
- **视图层（View）**：负责界面显示、用户交互和数据绑定

这种架构使得插件代码更加清晰，职责分明，便于维护和扩展。

### 2.3 开发流程

1. 创建插件类库工程
2. 引用 BOS 平台组件（website\bin 目录下）
3. 修改插件类库编译输出路径为 website\bin
4. 创建插件类，继承 AbstractBillPlugIn
5. 实现必要的事件方法
6. 在 BOS 设计器中配置单据维护插件

#### 4.1.3 案例 –销售出库单修改单据类型

**需求背景**：手工新增的销售出库单，单据类型不允许选择寄售单据类型。

**实现方案**：捕获 BeforeUpdateValue 事件，如果是在修改单据类型，则判断目标值，如果是"寄售单据类型"，则给出提示信息。

**关键代码**：

```csharp
public override void BeforeUpdateValue(BeforeUpdateValueEventArgs e)
{
    switch (e.Key.ToUpperInvariant())
    {
        case "FBILLTYPEID":
            string newbillTypeId = Convert.ToString(e.Value);
            string businessType = "";
            DynamicObject billTypePara = BusinessDataServiceHelper.LoadBillTypePara(this.Context, "SAL_OSBillTypeParaSetting", newbillTypeId);
            if (billTypePara != null)
            {
                businessType = Convert.ToString(billTypePara["BussinessType"]);
            }
            if (businessType.EqualsIgnoreCase("CONSIGNMENT") && 
                (this.View.OpenParameter.CreateFrom == CreateFrom.Default || 
                 this.View.OpenParameter.CreateFrom == CreateFrom.Copy))
            {
                this.View.ShowMessage("手工新增的销售出库单不允许选择寄售单据类型！");
            }
            break;
    }
}
```

## 5. 事件系统详解

### 5.1 事件分类

单据维护插件的事件可分为以下几类：

- **初始化事件**：OnInitialize, OnBillInitialize
- **数据加载事件**：LoadData, AfterLoadData
- **数据复制事件**：CopyData, AfterCopyData
- **保存事件**：BeforeSave, AfterSave
- **单据转换事件**：OnGetConvertRule, OnShowConvertOpForm
- **上下查事件**：OnShowTrackResult
- **引入事件**：VerifyImportData

### 5.2 常用事件详解

#### 5.2.1 OnBillInitialize

- **触发时机**：页面初始化时触发，在 OnInitialize 事件之后

- **应用场景**：初始化时设置控件属性、获取参数

- **示例代码**：

  ```csharp
  public override void OnBillInitialize(BillInitializeEventArgs e)
  {
      this.View.GetControl<EntryGrid>("FSTK_LOTADJUSTENTRY").SimplizationAllColumns();
  }
  ```

#### 5.2.2 LoadData

- **触发时机**：开始加载单据数据时触发

- **应用场景**：加载指定内码的单据，调整加载的单据数据包

- **示例代码**：

  ```csharp
  public override void LoadData(LoadDataEventArgs e)
  {
      object oId = this.View.OpenParameter.GetCustomParameter("Id");
      if (oId != null && !string.IsNullOrEmpty(oId.ToString()))
      {
          e.PrimaryKeyValue = oId;
          e.BizDataObject = BusinessDataServiceHelper.LoadSingle(this.Context, oId, this.View.BusinessInfo.GetDynamicObjectType());
      }
      base.LoadData(e);
  }
  ```

#### 5.2.3 AfterLoadData

- **触发时机**：单据数据加载完成后触发，此时模型还没有完成初始化

- **应用场景**：设置字段、菜单的可见性、可用性；少量的字段值调整

- **示例代码**：

  ```csharp
  public override void AfterLoadData(EventArgs e)
  {
      var value = this.Model.GetValue("FType");
      if (null != value && !string.IsNullOrWhiteSpace(value.ToString()))
      {
          this.View.StyleManager.SetVisible("FCostPattern", "FCostPattern", true);
          this.View.StyleManager.SetVisible("FIsDefault", "FIsDefault", true);
      }
      else
      {
          this.View.StyleManager.SetVisible("FCostPattern", "FCostPattern", false);
          this.View.StyleManager.SetVisible("FIsDefault", "FIsDefault", false);
      }
      base.AfterLoadData(e);
  }
  ```

#### 5.2.4 CopyData

- **触发时机**：单据进行复制操作，在获取到复制源数据之后触发

- **应用场景**：修改、调整复制的目标数据包

- **示例代码**：

  ```csharp
  public override void CopyData(CopyDataEventArgs e)
  {
      base.CopyData(e);
      var defaultTaxMixField = this.View.BusinessInfo.GetField("FDEFAULTISTAXMIX");
      if (defaultTaxMixField != null)
      {
          e.DataObject[defaultTaxMixField.PropertyName] = this.TaxMixOrTaxRate;
      }
  }
  ```

#### 5.2.5 AfterCopyData

- **触发时机**：单据进行复制操作，在复制目标数据包构建完成之后触发

- **应用场景**：对复制的目标数据包做最后的调整，修改

- **示例代码**：

  ```csharp
  public override void AfterCopyData(BOS.Core.Bill.PlugIn.Args.CopyDataEventArgs e)
  {
      base.AfterCopyData(e);
      foreach (DynamicObject entry in (e.DataObject["POOrderEntry"] as DynamicObjectCollection))
      {
          // 剩余收货数量
          entry["RemainReceiveQty"] = Convert.ToDecimal(entry["Qty"]) - Convert.ToDecimal(entry["ReceiveQty"]) + Convert.ToDecimal(entry["MrbQty"]);
          // 剩余入库数量
          entry["RemainStockInQty"] = Convert.ToDecimal(entry["Qty"]) - Convert.ToDecimal(entry["StockInQty"]);
      }
  }
  ```

#### 5.2.6 BeforeSave

- **触发时机**：保存操作，调用数据保存接口保存业务数据前触发

- **应用场景**：保存前客户端进行数据校验、调整保存的数据包

- **示例代码**：

  ```csharp
  public override void BeforeSave(BeforeSaveEventArgs e)
  {
      string reason = Convert.ToString(this.View.Model.GetValue("FChangeReason"));
      if (this.isOrderChange)
      {
          if (reason.IsNullOrEmptyOrWhiteSpace())
          {
              this.View.ShowMessage("变更原因必录！");
              e.Cancel = true;
              return;
          }
      }
  }
  ```

#### 5.2.7 AfterSave

- **触发时机**：保存操作，数据保存到数据库之后触发

- **应用场景**：保存完成之后更新界面元素的值、状态

- **示例代码**：

  ```csharp
  public override void AfterSave(AfterSaveEventArgs e)
  {
      base.AfterSave(e);
      if (this.View.ParentFormView != null && 
          this.View.ParentFormView.BillBusinessInfo.GetForm().Id.EqualsIgnoreCase("SUB_SUBREQORDER"))
      {
          this.View.ParentFormView.Refresh();
      }
  }
  ```

#### 5.2.8 OnGetConvertRule

- **触发时机**：选单/下推过程，获取单据转换规则时触发

- **应用场景**：弃用操作框里指定的转换规则，通过插件来获取新的单据转换规则

- **示例代码**：

  ```csharp
  public override void OnGetConvertRule(GetConvertRuleEventArgs e)
  {
      base.OnGetConvertRule(e);
      if (e.ConvertOperation == FormOperationEnum.Push && e.TargetFormId == "SP_PickMtrl")
      {
          ConvertRuleElement rule = ConvertServiceHelper.GetConvertRules(
              this.Context, "ENG_BomExpandBill", e.TargetFormId).FirstOrDefault();
          if (rule != null)
          {
              e.Rule = rule;
          }
      }
  }
  ```

#### 5.2.9 OnShowConvertOpForm

- **触发时机**：下推过程中，展示可选目标单据

- **应用场景**：调整可选的单据类型

- **示例代码**：

  ```csharp
  public override void OnShowConvertOpForm(ShowConvertOpFormEventArgs e)
  {
      base.OnShowConvertOpForm(e);
      if (e.ConvertOperation == FormOperationEnum.Push)
      {
          var bills = e.Bills as List<ConvertBillElement>;
          if (bills != null && bills.Count > 0)
          {
              e.Bills = bills.Where(c => !c.FormID.Equals("FA_CARD", StringComparison.OrdinalIgnoreCase)).ToList();
          }
      }
  }
  ```

#### 5.2.10 OnShowTrackResult

- **触发时机**：上/下查过程，获得上/下查结果

- **应用场景**：调整上/下查结果，调整结果显示

- **示例代码**：

  ```csharp
          if (e.TrackResult != null)

              {
                  // 替换上查结果的逻辑
              }
          }
      }
  }
  ```

#### 5.2.11 VerifyImportData

- **触发时机**：引入操作，在读取引入文件将数据组装成关系型数据行之后，开始填充单据数据包之前触发

## 6. 典型案例分析

### 6.1 批号调整单明细单据体不支持排序案例

**需求背景**：批号调整单明细单据体显示的批号调整明细信息是分组的，组内按调整前、调整后排序，用户在单据体上进行分组、排序会打乱这个显示。

**实现方案**：在 OnBillInitialize 事件中，将明细单据体强制所有列为简单列，不支持分组、排序。

```csharp
public override void OnBillInitialize(BillInitializeEventArgs e)

}
```

### 6.5 采购订单复制后计算数量案例

**需求背景**：采购订单在复制之后，订单明细单据体需要根据数量和累计收料数量，计算剩余收货数量、剩余入库数量和交货明细子单据体上的几个剩余数量。

**实现方案**：在 AfterCopyData 事件中，计算并设置剩余数量字段的值。

**关键代码**：

```csharp
public override void AfterCopyData(BOS.Core.Bill.PlugIn.Args.CopyDataEventArgs e)
{
    base.AfterCopyData(e);
    foreach (DynamicObject entry in (e.DataObject["POOrderEntry"] as DynamicObjectCollection))
    {
        // 剩余收货数量
        entry["RemainReceiveQty"] = Convert.ToDecimal(entry["Qty"]) - Convert.ToDecimal(entry["ReceiveQty"]) + Convert.ToDecimal(entry["MrbQty"]);
        // 剩余入库数量
        entry["RemainStockInQty"] = Convert.ToDecimal(entry["Qty"]) - Convert.ToDecimal(entry["StockInQty"]);
        // 交货明细剩余数量
        foreach (DynamicObject plandetail in (DynamicObjectCollection)entry["POOrderEntryDeliPlan"])
        {
            plandetail["DeliRemainQty"] = Convert.ToDecimal(plandetail["PlanQty"]) - Convert.ToDecimal(plandetail["DeliCommitQty"]);
            plandetail["BaseDeliRemainQty"] = Convert.ToDecimal(plandetail["BasePlanQty"]) - Convert.ToDecimal(plandetail["BaseDeliCommitQty"]);
        }
    }
}
```

## 7. 最佳实践

### 7.1 开发技巧

1. **事件处理顺序**：了解单据生命周期中事件的执行顺序，合理安排代码逻辑
2. **参数传递**：使用 OpenParameter 或自定义参数传递数据，避免硬编码
3. **异常处理**：在关键操作中添加异常处理，提高插件稳定性
4. **日志记录**：在复杂逻辑中添加日志记录，便于调试和问题排查
5. **控件操作**：使用 GetControl<T> 获取控件并进行操作，避免直接操作界面元素

### 7.2 性能优化

1. **数据查询优化**：合理使用过滤条件，避免全表扫描
2. **缓存使用**：对于频繁访问的数据，考虑使用缓存
3. **批量操作**：对于批量数据处理，使用批量操作减少数据库交互
4. **延迟加载**：对于非必要的数据，使用延迟加载提高响应速度
5. **减少数据库交互**：尽量减少数据库查询次数，合并查询语句

### 7.3 代码规范

1. **命名规范**：使用有意义的类名、方法名和变量名
2. **注释规范**：为关键方法和复杂逻辑添加注释
3. **代码结构**：保持代码结构清晰，逻辑分明
4. **代码复用**：提取公共方法，避免代码重复
5. **遵循框架**：遵循 BOS 平台的开发规范和最佳实践

### 7.4 常见问题及解决方案

| 问题           | 原因             | 解决方案                                     |
| -------------- | ---------------- | -------------------------------------------- |
| 插件不触发事件 | 事件方法签名错误 | 检查方法签名是否正确，确保使用正确的参数类型 |
| 数据加载失败   | 主键值不正确     | 检查 LoadData 事件中的主键值设置             |
| 保存失败       | 数据校验不通过   | 检查 BeforeSave 事件中的校验逻辑             |
| 下推无目标单据 | 转换规则未配置   | 检查 OnGetConvertRule 事件中的转换规则设置   |
| 控件操作无效   | 控件获取方式错误 | 使用正确的控件类型和键名获取控件             |
| 性能缓慢       | 数据处理逻辑复杂 | 优化数据处理逻辑，使用缓存和批量操作         |
