# 金蝶云星空单据服务插件学习总结

## 1. 引言

### 1.1 术语定义

- **操作插件**：用于对操作的执行过程进行干预、控制，以实现自定义扩展功能的插件
- **事务**：数据库操作的一个执行单元，要么全部执行成功，要么全部失败回滚
- **校验器**：用于检查数据是否符合业务规则的组件
- **数据包**：包含单据所有字段数据的对象

## 2. 核心概念

### 2.1 操作插件原理

操作插件是K/3 Cloud系统中实现业务操作扩展的重要机制，通过介入到操作的各个关键时刻，对操作行为进行控制，从而实现自定义的业务逻辑。操作插件可以在操作执行的不同阶段进行干预，如数据校验、业务处理、结果处理等。

### 2.2 操作插件的工作机制

1. **初始化阶段**：设置操作执行参数，准备需要加载的字段
2. **校验阶段**：添加自定义校验器，检查数据是否符合业务规则
3. **执行阶段**：在事务内外执行业务逻辑
4. **结果处理阶段**：处理操作结果，修饰提示信息

### 2.3 与其他插件类型的区别

| 特性 | 操作插件 | 单据插件 | 列表插件 |
|------|---------|---------|----------|
| 作用范围 | 特定操作 | 整个单据生命周期 | 列表界面操作 |
| 触发时机 | 操作执行过程中 | 单据各种事件 | 列表加载和操作 |
| 核心功能 | 控制操作执行过程 | 控制单据界面和数据 | 控制列表显示和操作 |
| 事务支持 | 可在事务内外执行 | 通常在事务外执行 | 通常在事务外执行 |

## 4. 插件启用与配置

### 4.1 插件编译与部署

1. 编写完插件代码后，编译生成DLL文件
2. 将生成的类库文件(*.dll)复制到K/3 Cloud安装目录的WebSite\Bin子目录

### 4.2 BOS设计器中的配置方法

1. 进入BOS设计器，打开单据操作配置界面
2. 找到对应的操作（如保存、审核、反审核等）
3. 配置服务插件，选择要启用的操作插件
4. 保存配置并发布

### 4.3 部署注意事项

- 确保插件类库与K/3 Cloud版本兼容
- 部署前备份原有文件
- 部署后重启应用池
- 在测试环境验证后再部署到生产环境

## 6. 事件系统

### 6.1 事件执行顺序

#### 完整的事件触发流程

1. OnPrepareOperationServiceOption
2. OnPreparePropertys
3. OnAddValidators
4. BeforeExecuteOperationTransaction
5. BeginOperationTransaction
6. EndOperationTransaction
7. AfterExecuteOperationTransaction

#### 事件执行时机

| 事件 | 执行时机 | 事务状态 | 主要作用 |
|------|---------|---------|----------|
| OnPrepareOperationServiceOption | 初始化操作执行参数 | 事务外 | 设置操作执行选项 |
| OnPreparePropertys | 加载单据数据前 | 事务外 | 指定需要加载的字段 |
| OnAddValidators | 数据校验前 | 事务外 | 添加自定义校验器 |
| BeforeExecuteOperationTransaction | 正式执行操作前 | 事务外 | 前期数据准备 |
| BeginOperationTransaction | 启动事务后 | 事务内 | 操作前的业务处理 |
| EndOperationTransaction | 操作处理完毕，未提交事务前 | 事务内 | 操作后的业务处理 |
| AfterExecuteOperationTransaction | 事务提交完毕后 | 事务外 | 处理操作结果 |

### 6.2 核心事件详解

#### OnPrepareOperationServiceOption

**作用**：初始化操作执行参数，控制操作执行策略

**语法**：

```csharp
public virtual void OnPrepareOperationServiceOption(OnPrepareOperationServiceEventArgs e)
```

**参数说明**：
- SurportBatchTransaction：是否整批数据放在一个事务中处理
- SupportTransaction：是否开启事务
- AllowSetOperationResult：是否允许平台自动添加操作成功的消息
- RollbackWhenValidationError：校验错误时是否回滚整批操作

**使用场景**：
- 控制事务行为
- 设置操作执行选项

**案例**：初始化库存保存

```csharp
public override void OnPrepareOperationServiceOption(
    OnPrepareOperationServiceEventArgs e)
{
    base.OnPrepareOperationServiceOption(e);
    //为了在EndOperationTransaction里检查数据抛出交互异常的时候
    //只回滚当前单据的事务，这里设置为不支持批量事务，这样BOS会
    //循环为每一张单据创建事务调用操作
    e.SupportTransaction = true;
    e.SurportBatchTransaction = false;
}
```

```csharp
public override void EndOperationTransaction(EndOperationTransactionArgs e)
{
    long supplierId = 0;
    long discountListId = 0;
    bool defDiscountListId = false;
    List<string> sqlArray = new List<string>();
    foreach (DynamicObject entity in e.DataEntitys)
    {
        if (entity != null)
        {
            supplierId = Convert.ToInt64(entity["supplierId_Id"]);
            discountListId = Convert.ToInt64(entity["Id"]);
            defDiscountListId = Convert.ToBoolean(entity["DefDiscountListId"]);
            if (discountListId > 0 && supplierId > 0 && defDiscountListId)
            {
                string sql = string.Format(@"UPDATE T_BD_SUPPLIERBUSINESS AS P
SET FDISCOUNTLISTID= {0}
WHERE P.FSupplierid={1} ", discountListId.ToString(), supplierId.ToString());
                sqlArray.Add(sql);
            }
        }
    }
    if (sqlArray.Count > 0)
    {
        DBUtils.ExecuteBatch(this.Context, sqlArray, 100);
    }
}
```

## 8. 最佳实践

### 8.1 插件开发规范

1. **命名规范**：遵循[开发商].K3[.业务领域][.子系统].ServicePlugIn命名规范
2. **代码风格**：保持与K/3 Cloud系统代码风格一致
3. **注释规范**：为关键方法和复杂逻辑添加详细注释
4. **异常处理**：合理处理可能出现的异常情况
5. **日志记录**：关键操作添加日志记录，便于问题排查

### 8.2 性能优化建议

1. **字段加载**：只加载必要的字段，避免加载过多字段影响性能
2. **事务管理**：减少事务占用时间，把非数据更新操作放在事务外
3. **批量处理**：对大量数据的处理要考虑分批处理
4. **缓存使用**：合理使用缓存，避免重复计算
5. **SQL优化**：优化查询语句，避免全表扫描

### 8.3 常见问题及解决方案

**问题1**：插件不被触发

- **原因**：插件未正确注册或操作配置错误
- **解决方案**：检查插件注册和操作配置

**问题2**："属性不存在"错误

- **原因**：插件需要用到的字段未在OnPreparePropertys事件中声明加载
- **解决方案**：在OnPreparePropertys事件中添加需要的字段

**问题3**：事务回滚问题

- **原因**：在事务外执行了需要回滚的操作
- **解决方案**：把需要回滚的操作放在事务内执行

**问题4**：性能问题

- **原因**：加载字段过多或数据处理逻辑复杂
- **解决方案**：优化字段加载，简化处理逻辑

**问题5**：操作结果处理问题

- **原因**：在AfterExecuteOperationTransaction事件中尝试修改数据
- **解决方案**：在事务内的事件中处理数据修改，在事务外的事件中只处理结果
